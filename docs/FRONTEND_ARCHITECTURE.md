# Frontend Architecture

The frontend of Joyory AI LookMatch is built with React, Vite, TypeScript, and Tailwind CSS. It is designed to be a fast, responsive, and visually appealing Single Page Application (SPA).

## Core Technologies

- **React**: Used for building the component-based user interface.
- **Vite**: The build tool and development server, providing extremely fast Hot Module Replacement (HMR).
- **TypeScript**: Adds static typing to JavaScript, improving developer experience and catching errors early.
- **Tailwind CSS**: A utility-first CSS framework used for all styling, allowing for rapid UI development without writing custom CSS files.

## Application Entry Point

The entry point of the application is `src/main.tsx`, which renders the root `<App />` component into the DOM. The global styles are imported from `src/index.css`, which contains the Tailwind directives and custom CSS variables.

## Main Components

The entire application structure is currently contained within `src/App.tsx`. This monolithic structure was chosen for rapid prototyping but is divided logically into several key sections:

### 1. `App` (Root Component)
- Manages global state such as the `cartCount`, `showToast`, and the loaded `products` catalog.
- Fetches the initial product data from `GET /api/products` using a `useEffect` hook.
- Renders all the other major sections of the page sequentially (Navbar, Hero, Categories, FeaturedProducts, etc.).

### 2. `AILookMatch`
- The core feature of the application. It allows users to interact with the AI matching engine in two ways, managed by an `activeTab` state:
  - **Quick Select (Chips)**: Users click feature chips (e.g., 'vegan', 'hydrating'). The component tracks these in the `selectedFeatures` state and sends them to `POST /api/match`.
  - **Describe Look (Text)**: Users type a natural language prompt. The component sends this to `POST /api/ai/product-name` to get structured attributes, and then passes those attributes to `POST /api/match`.
- **State Management**:
  - `matchedResults`: Stores the array of `MatchResult` objects returned by the backend.
  - `loading`, `searched`, `textError`: Manage the UI feedback states during API calls.
- **Rendering Results**: Maps over `matchedResults` to render a grid of `ProductCard` components, passing down the specific `matchReasons` generated by the backend.

### 3. `FeaturedProducts`
- Receives the full `products` array as a prop.
- Dynamically extracts unique product categories to build the filter tabs (e.g., 'All', 'Skincare', 'Makeup').
- Filters and displays a grid of `ProductCard` components based on the `activeTab`.

### 4. `ProductCard`
- A reusable UI component for displaying a single product.
- **Props**: Accepts a generic `product` object (can be a full `Product` or a subset from a `MatchResult`), an optional `matchScore`, an optional array of `matchReasons`, and an `onAddToCart` callback.
- **Dynamic Display**: If `matchReasons` are provided (from the AI LookMatch), it displays them in highlighted pills to explain *why* the product matched. Otherwise, it defaults to showing the product's general `features`.

## API Communication & Proxy

To avoid Cross-Origin Resource Sharing (CORS) issues during development, the Vite development server is configured to proxy API requests.

In `vite.config.ts`:
```typescript
export default defineConfig({
  // ...
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true
      }
    }
  }
})
```
This means any `fetch('/api/...')` call from the React app is automatically routed to the FastAPI backend running on port 8000. No manual absolute URLs are needed in the fetch calls.
